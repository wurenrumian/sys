AllReduce 通信模型:  T = 通信轮数 x 单跳延迟  +  传输字节 / 带宽

[1] 固定数据量 1GB (约 250M 参数的 fp32 梯度), 链路 = InfiniBand 25GB/s / 2.5us

       卡数     Naive(中心汇聚)            Ring             二项树          递归折半HD      Ring带宽占比
  ------------------------------------------------------------------------------------
        8        560.0ms         70.0ms        240.0ms         70.0ms       100.0%
       64       5040.0ms         79.1ms        480.0ms         78.8ms        99.6%
      256      20400.0ms         81.0ms        640.0ms         79.7ms        98.4%
     1024      81840.0ms         85.0ms        800.1ms         80.0ms        94.0%
     4096     327600.0ms        100.5ms        960.1ms         80.0ms        79.6%

  -> Naive 完全不可扩展: 中心节点传输量随卡数线性增长, 4096 卡要 5 分钟.
     Ring 的**带宽项**与卡数几乎无关(趋近 2D, 这是它的精髓),
     但它要走 2(n-1) 步, 延迟项随卡数**线性**增长.
     看最后一列: 8 卡时 Ring 的耗时几乎全是有效数据传输(带宽占比高),
     到 4096 卡时带宽占比降到 80% 以下 —— 有 20% 的时间纯粹耗在通信轮次的
     延迟累积上. 这就是表格里'卡间通信开销随卡数变多而效率变低'的数学来源.
     二项树因为每步都要传完整的 D, 带宽项随 log n 增长, 大数据量下最差.

[2] Ring vs Tree 的交叉点: 取决于数据量 (1024 卡, InfiniBand)

         数据量         Ring          二项树        递归折半HD    Ring vs 树
  ----------------------------------------------------------------
         1KB       5115us         51us          50us           树赢
        10KB       5116us         58us          51us           树赢
       100KB       5123us        130us          58us           树赢
         1MB       5195us        850us         130us           树赢
        10MB       5914us       8050us         849us       Ring 赢
       100MB      13107us      80050us        8042us       Ring 赢
      1000MB      85037us     800050us       79972us       Ring 赢

  -> 交叉点清晰可见:
     * 小数据量: 被**延迟**支配 -> 树赢(2*log n 轮 vs Ring 的 2(n-1) 轮).
       1024 卡下 Ring 要走 2046 轮, 光延迟累积就 5.1ms; 树只要 20 轮.
     * 大数据量: 被**带宽**支配 -> Ring 赢(单卡传输量趋近 2D 且与 n 无关,
       而二项树每步传完整 D, 总量达 2*log2(n)*D = 20D).

     注意第三列: 递归折半(HD)在这个理想模型里**全程最优** —— 它同时拿到了
     树的 log n 轮数和 Ring 的最优传输量. 但它要求卡数为 2 的幂, 且通信对端
     跨越拓扑层级, 在真实分层网络里未必划算(详见函数注释).
     NCCL 会根据数据量、卡数、拓扑在这几种算法间自动选择.
     推荐场景的特殊性: 稀疏参数的 AllToAll 通信量既大又不规则,
     以上算法都不直接适用 —— 这正是可以做文章的地方.

[3] 异构网络: 同样 1024 卡 1GB, 不同链路差多少

  链路类型                            带宽        延迟       Ring 耗时      相对最快
  --------------------------------------------------------------------
  NVLink (机内)              450.0GB/s      1.0us         6.5ms      1.0x
  InfiniBand (机间)           25.0GB/s      2.5us        85.0ms     13.1x
  RoCE 以太网                  12.5GB/s      5.0us       170.1ms     26.2x

  -> 带宽差 36 倍, 通信耗时差 26 倍 (不完全成比例, 因为延迟项也在变). 而真实集群是**分层**的:
     机内 NVLink 快, 机间 IB 慢 -> 必须用**分层 AllReduce**
     (先机内规约, 再机间规约, 最后机内广播), 把慢链路上的数据量降到 1/8.
     表格里'异构网络环境中带宽差异达数十倍且拓扑层级复杂'说的就是这件事.

--------------------------------------------------------------------------------------
[4] 分层 AllReduce 的收益 (1024 卡 = 128 机 x 8 卡)

  扁平 Ring (1024 卡全走 IB)        :    85.04 ms
  分层 AllReduce                    :    14.46 ms  (5.88x 加速)
    ├─ 机内 reduce-scatter (NVLink) :     1.95 ms
    ├─ 机间 AllReduce   (IB, 仅 D/8) :    10.56 ms
    └─ 机内 all-gather     (NVLink) :     1.95 ms

  收益的全部来源: 机间(慢链路)上的数据量从 D 降到了 D/8.
  扁平方案里 85ms 几乎全部花在 IB 上; 分层后 IB 只需搬 1/8 的数据,
  剩下的规约工作交给快 18 倍的机内 NVLink 完成.
  这就是'拓扑感知'的价值: 同样的数学结果, 把数据搬运安排在正确的链路上.

[对应到表格的课题]
  TikTok 那条列的探索方向, 现在可以对号入座了:
  * '算子级通信/计算重叠' —— 上面算的都是**纯通信**时间. 如果能让通信
    藏在计算的空隙里, 这些时间就等于免费. 这是收益最大的方向.
  * '有损压缩通信(梯度量化/稀疏化)' —— 直接减小上面公式里的 D.
    fp32->fp8 就是 4x, 但要保证 AUC 不掉(和 01 目录的 DCAI 是同一类问题).
  * 'Asynchronous Pipeline Parallelism(允许微小版本差异)' —— 打破同步屏障,
    让通信不再是关键路径上的阻塞点.
  * '自适应多路径路由(Fat-Tree/Torus 避热点)' —— 上面模型假设带宽是常数,
    真实网络里链路会拥塞, 有效带宽远低于标称值.

  注意本 demo 的模型只是**下界**: 它假设了完美的带宽、零拥塞、零抖动.
  真实千卡训练还要面对慢节点(straggler)、网络抖动、故障重传 ——
  表格里'单卡出问题都会导致训练不稳定, 卡多后概率也更高'说的就是这个.
