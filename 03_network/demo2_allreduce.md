# demo2 · AllReduce：千卡之后通信效率为什么变低

> Ring 带宽最优、Tree 延迟最优、递归折半理论上两项都最优 —— 而工业上仍大量用 Ring。

---

## 一、真实场景：这段代码对应线上的什么

数据并行训练里，每个 step 结束时所有卡必须把梯度**加起来再分发回去**，这就是 AllReduce：

```
卡0 梯度 g0 ┐
卡1 梯度 g1 ├─→  所有卡都拿到 (g0+g1+...+gN)  ─→  各自更新参数
...         │
卡N 梯度 gN ┘
```

这是**同步屏障**：任何一张卡没到齐，所有卡都得等。所以它直接坐在关键路径上。

表格里点名了两件事：

- TikTok："训练任务达到千卡规模后（H100/B200），IO 和通信效率变低……
  卡间通信开销会随着卡数变多而效率变低"
- 网络方向："异构网络环境中（NVLink/InfiniBand/RoCE 以太网）的带宽差异达数十倍且拓扑层级复杂"

**这不是玄学，是可以算的。** 这个 demo 就是把它算清楚。

---

## 二、这个 demo 具体干了什么（流程）

不做模拟，做**解析建模** —— 用经典的 **alpha-beta 模型**：

```
T = 通信轮数 × 单跳延迟(α)  +  单卡传输字节 / 带宽(β)
     └── 延迟项 ──┘            └──── 带宽项 ────┘
```

四组实验：

1. **规模扩展**：固定 1GB 数据，卡数 8 → 4096，看四种算法的耗时，
   以及 Ring 的"带宽项占比"（用来量化延迟累积的伤害）
2. **交叉点**：固定 1024 卡，数据量 1KB → 100MB，看 Ring 和 Tree 谁赢
3. **异构网络**：同样 1024 卡 1GB，NVLink / IB / RoCE 三种链路
4. **分层 AllReduce**：1024 卡 = 128 机 × 8 卡，扁平 vs 分层

## 三、涉及的算法（这一节是本 demo 的主体）

### Naive（中心汇聚）

所有卡把数据发给 rank0，rank0 归约后广播回去。

```
轮数 = 2
中心节点传输量 = 2·(N-1)·D        ← 单点瓶颈，随 N 线性增长
```

**完全不可扩展。** 4096 卡时中心节点要搬 8TB，要跑 5 分钟。

### Ring AllReduce（带宽最优）

分两阶段，各 N-1 步。所有卡排成一个环，每步只和左右邻居通信：

```
阶段1 reduce-scatter：把数据切成 N 块。第 k 步，每张卡把手上某一块发给右邻居、
                       同时从左邻居收一块累加。N-1 步后，每卡持有 1/N 的完整规约结果。
阶段2 all-gather：     再转 N-1 步，把各自那 1/N 的结果传遍全环。

轮数 = 2(N-1)                    ← 延迟项随 N 【线性】增长
单卡传输量 = 2·(N-1)/N·D → 2D    ← 带宽项与 N 【几乎无关】，这是它的精髓
```

### 二项树（Reduce + Broadcast）

```
轮数 = 2·log₂N                   ← 延迟项只随 log N 增长
每步传输完整的 D 字节 → 总量 2·log₂N·D    ← 带宽项随 log N 【增长】
```

### 递归折半-加倍（Recursive Halving-Doubling）

每步和"距离 2^k"的对端交换，传输量逐步减半再加倍：

```
轮数 = 2·log₂N                   ← 和树一样好
总传输量 ≈ 2·(N-1)/N·D           ← 和 Ring 一样好
```

**理论上两项同时最优。** 那为什么工业界还大量用 Ring？三个现实原因（代码注释里也写了）：

1. HD 要求卡数是 2 的幂，否则要补零或退化；
2. HD 的通信对端是"距离 2^k 的卡"，在分层拓扑上会**跨交换机**；
   而 Ring 的通信永远发生在相邻节点，**对物理拓扑更友好**；
3. Ring 实现简单，对非均匀带宽更鲁棒。

> 这是一个很好的提醒：**理论最优的算法未必是工程最优的**，
> 因为模型里"一次通信"的成本被假设成常数，而真实网络里它取决于走哪条路。

### 分层 AllReduce（拓扑感知）

```
机内 reduce-scatter (NVLink，快)  →  每卡只持有 D/8
机间 AllReduce      (IB，慢)      →  只需要在 D/8 上做   ← 收益全部来自这里
机内 all-gather     (NVLink，快)  →  广播回去
```

**慢链路上的数据量直接降到 1/8。** 同样的数学结果，只是把数据搬运安排在了正确的链路上。

## 四、方案对比

| 算法 | 轮数（延迟项） | 单卡传输量（带宽项） | 适用 | 致命弱点 |
|---|---|---|---|---|
| **Naive** | 2 | (N-1)·D | 几乎没有 | 中心节点单点瓶颈 |
| **Ring** | 2(N-1) | 2·(N-1)/N·D ≈ 2D | **大数据量**（带宽支配） | 千卡后延迟项累积 |
| **二项树** | 2·log₂N | 2·log₂N·D | **小数据量**（延迟支配） | 大数据量时带宽项爆炸 |
| **递归折半 HD** | 2·log₂N | ≈ 2D | 理论最优 | 要求 2 的幂；跨拓扑层级 |
| **分层** | 组合 | 慢链路上只有 D/G | **分层网络的实际选择** | 需要拓扑信息 |

**NCCL 实际会根据数据量、卡数、拓扑在这几种之间自动选择。**

## 五、怎么读输出

### `[1] 规模扩展`（固定 1GB，IB 25GB/s）

```
   卡数     Naive(中心汇聚)      Ring        二项树   递归折半HD   Ring带宽占比
      8            560.0ms      70.0ms     240.0ms      80.0ms       100.0%
   1024        73142.9ms      85.1ms     800.1ms      80.1ms        94.0%
   4096       292500.0ms     100.5ms     960.1ms      80.1ms        79.6%
```

- **Naive 4096 卡要 5 分钟** → 完全不可扩展。
- **Ring 从 8 卡的 70ms 到 4096 卡的 100.5ms**，只涨了 44% —— 带宽项确实与卡数无关。
- **看最后一列（Ring 带宽占比）**：8 卡时 100%（时间全花在有效数据传输上），
  4096 卡时降到 79.6% —— **有 20% 的时间纯粹耗在通信轮次的延迟累积上**。

> **这就是"卡间通信开销随卡数变多而效率变低"的数学来源。**
> 不是网络变慢了，是你要走的轮数变多了，而每一轮都要付一次单跳延迟。

### `[2] Ring vs Tree 交叉点`（1024 卡）

```
   数据量        Ring        二项树   递归折半HD    Ring vs 树
      1KB      5115us         51us         50us          树赢
      1MB      5195us        850us        130us          树赢
     10MB      5914us       8050us        849us       Ring 赢
    100MB     13107us      80050us       8042us       Ring 赢
```

- **小数据量被延迟支配** → 树赢。1024 卡下 Ring 要走 2046 轮，光延迟累积就 5.1ms；树只要 20 轮。
- **大数据量被带宽支配** → Ring 赢。树每步传完整 D，总量达 2·log₂(1024)·D = 20D。
- **第三列 HD 全程最优**（理论模型里），原因见上面的算法部分。

### `[3] 异构网络`

```
  链路类型                 带宽       延迟     Ring 耗时   相对最快
  NVLink (机内)      450.0GB/s     1.0us      6.6ms       1.0x
  InfiniBand (机间)   25.0GB/s     2.5us     85.1ms      12.9x
  RoCE 以太网         12.5GB/s     5.0us    170.2ms      25.8x
```

带宽差 36 倍，通信耗时差 26 倍（不完全成比例，因为延迟项也在变）。

### `[4] 分层 AllReduce`

```
  扁平 Ring (1024 卡全走 IB)        :    85.13 ms
  分层 AllReduce                    :    12.24 ms  (6.95x 加速)
    ├─ 机内 reduce-scatter (NVLink) :     0.20 ms
    ├─ 机间 AllReduce   (IB, 仅 D/8) :    11.85 ms
    └─ 机内 all-gather     (NVLink) :     0.20 ms
```

**收益的全部来源：机间（慢链路）上的数据量从 D 降到了 D/8。**
扁平方案里 85ms 几乎全花在 IB 上；分层后 IB 只需搬 1/8 的数据，
剩下的规约工作交给快 18 倍的机内 NVLink 完成。

## 六、动手：改参数能验证什么

| 参数 | 调成 | 会发生什么 | 说明了什么 |
|---|---|---|---|
| `D_GB` | 1.0 → 0.001 | `[1]` 里树和 HD 反超 Ring | **交叉点是真的**，不是理论推测 |
| `IB_LAT_US` | 2.5 → 20 | Ring 的带宽占比在 1024 卡就掉到很低 | 延迟项的伤害 ∝ 单跳延迟 × 轮数。**低延迟网络对大规模训练比高带宽更关键** |
| `IB_GBPS` | 25 → 100 | 带宽项缩小，延迟项占比相对上升 | 光堆带宽，边际收益会被延迟项吃掉 |
| `GPUS_PER_NODE` | 8 → 2 | 分层的加速比从 ~7x 掉到 ~2x | **分层收益 ≈ 每机卡数**。这解释了为什么厂商拼命往一台机器里塞卡 |
| `GPUS_PER_NODE` | 8 → 16 | 加速比进一步提升 | 同上，从另一个方向验证 |

**建议做 `GPUS_PER_NODE` 那两个实验**：它把"为什么 NVLink 域越大越好""为什么 NVL72 这种
机柜级互联是趋势"这件事，变成了一个你能自己算出来的数字。

## 七、这个模型的边界（重要）

alpha-beta 模型给的是**下界**，它假设了：完美带宽、零拥塞、零抖动、无故障。
真实千卡训练还要面对：

- **慢节点（straggler）**：同步屏障意味着所有人等最慢的那个（和 `03/demo4` 的 tail-at-scale 同构）
- **网络抖动与拥塞**：有效带宽远低于标称值
- **故障重传**：表格里"单卡出问题都会导致训练不稳定，卡多后概率也更高"说的就是这个

## 八、对应到表格的探索方向

| 方向 | 它在这个模型里对应什么 |
|---|---|
| **算子级通信/计算重叠** | 上面算的都是**纯通信**时间。能藏进计算空隙里的部分就等于免费 —— 收益最大的方向（但上限受计算时长限制，见 `04/demo1`） |
| **有损压缩通信**（梯度量化/稀疏化） | 直接减小公式里的 D。fp32→fp8 就是 4x，但要保证 AUC 不掉（和 `01/demo3` 是同一类问题） |
| **异步流水并行**（允许版本差） | 打破同步屏障，让通信不再是关键路径上的阻塞点 |
| **自适应多路径路由** | 上面假设带宽是常数，真实网络里链路会拥塞 |
