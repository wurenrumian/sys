# demo3 · DCAI：数据事故如何静悄悄打掉线上 AUC

> 模型代码一行没改，只是上游数据出了问题，AUC 就掉了 2 个点 —— 而最常用的漂移指标 PSI 报"正常"。

---

## 一、真实场景：这段代码对应线上的什么

推荐系统的线上模型每天都在被"数据事故"偷袭。典型的四种：

| 事故 | 现实中怎么发生的 | 表现 |
|---|---|---|
| **特征缺失** | 上游某个特征生产任务挂了/超时，下游取到默认值 0 | 某个特征全变成同一个值 |
| **口径变更** | 上游把"播放时长"从秒改成毫秒；或换了归一化方式，没通知下游 | 分布整体平移 + 缩放 |
| **离在线不一致** | 线上 serving 取到的是上一版本的特征；或离线 Spark 和在线 C++ 的实现有细微差异 | **只有部分流量**受影响，均值几乎没变 |
| **特征不新鲜** | 数据管道积压，用了几小时前的特征 | 全特征叠加噪声 |

共同点：**模型代码一行没改，发布系统一片绿，但线上收入在掉。**
而且往往过了好几天，才有人从业务指标反查到是数据的问题。

所以工业上必须有一套**数据质量监控**在模型之前拦住它。这对应表格里的：
"推荐大模型对数据质量敏感度提升，数据分布异常可能导致模型效果显著下降，亟需系统性数据质量评估与改进方法"
以及 DCAI（Data-Centric AI）："通过数据质量优化与自动化处理链路提升模型性能，而非单纯依赖模型改进"。

## 二、这个 demo 具体干了什么（流程）

### 第 1 步：造一个有真实信号的数据集

```python
X ~ N(0,1)，12 维
w = [1.4, 1.1, 0.9, 0.7, 0.15, 0.15, ...]      # 前 4 维信号强，其余弱
y = Bernoulli(sigmoid(X·w - 1.0))
```

**权重刻意做成长尾**，模拟推荐特征的重要性分布：少数几个特征扛大梁，几百个特征各贡献一点。

### 第 2 步：训练一个最小的排序模型

一个纯 numpy 的逻辑回归（250 轮全批量梯度下降）。**重点不在模型**——
它只是一个"下游消费者"，用来测量数据变坏时业务指标掉多少。

### 第 3 步：在**线上样本**上注入四种事故

注意：训练集不动，只污染 serving 集。这正是线上事故的形态 —— 模型是好的，喂给它的数据坏了。

```python
incident_missing:  Xb[:, 0] = 0.0                        # feat_0 全变默认值
incident_shift:    Xb[:, 1] = Xb[:, 1] * 2.5 + 1.8       # feat_1 平移+缩放
incident_skew:     30% 的行，feat_2 换成与 label 无关的随机值
incident_stale:    全部特征 + N(0, 0.35) 噪声
```

### 第 4 步：对每种事故同时测两个东西

- **AUC**：业务真正在乎的（用秩和法算，不依赖 sklearn）
- **PSI**：监控系统真正在看的（逐特征算，取最大值报警）

然后把两者放在同一张表里对照 —— **这个对照就是整个 demo 的设计核心**。

### 第 5 步：画敏感度曲线

把 feat_0 的污染比例从 0% 扫到 100%，看 AUC 和 PSI 各自怎么走。

## 三、涉及的算法

### AUC（秩和法）

```
AUC = (正样本秩和 - n₁(n₁+1)/2) / (n₁ · n₀)
```

等价于"随机取一正一负，模型给正样本打分更高的概率"。代码里还处理了并列值（同分取平均秩），
否则打分有大量重复时 AUC 会算错。

### PSI（Population Stability Index）

```
PSI = Σᵢ (实际占比ᵢ - 期望占比ᵢ) × ln(实际占比ᵢ / 期望占比ᵢ)

判定：< 0.1 稳定  |  0.1 ~ 0.25 需关注  |  > 0.25 显著漂移，必须报警
```

它其实是 KL 散度的对称化版本（Jeffreys divergence）的分桶估计。

**一个关键实现细节**：分桶边界取自**训练期**分布的分位数，并且必须**冻结**：

```python
edges = np.quantile(expect, linspace(0,1,bins+1))   # 边界来自期望分布
edges[0], edges[-1] = -inf, +inf                     # 两端开放，防止新数据越界丢失
```

如果边界跟着实际分布自适应地重算，漂移会被分桶悄悄吸收掉，指标永远看起来正常。
**这是 PSI 实现里最常见的 bug。**

### 空值率 / 默认值率

```python
null_rate(col) = mean(col == default)
```

最朴素的统计指标，但对"生产任务挂掉"这类事故是**最灵敏**的。

---

### 其余五个对比指标

| 指标 | 公式/做法 | 属于哪一类 | 相对 PSI 的差别 |
|---|---|---|---|
| **KS** | 两个经验 CDF 的最大垂直距离 | 边缘分布 | 不依赖分桶；对平移更敏感 |
| **JS 散度** | KL 的对称有界版本（0~ln2） | 边缘分布 | 数值稳定得多（PSI 在空桶时会爆炸） |
| **Wasserstein-1** | 分位数差的平均（推土机距离） | 边缘分布 | **带量纲**，对平移线性敏感而非饱和 |
| **单特征 AUC 漂移** | 只用该特征排序的 AUC，训练期 vs 线上期 | **关联类** | **唯一用到 label**，能看见"特征↔label 的关系" |
| **互信息漂移** | I(X;Y) 的分桶估计，训练期 vs 线上期 | **关联类** | 能抓非单调关联（AUC 只看单调排序能力） |

## 四、方案对比：四类监控信号各自能抓什么

| 监控类型 | 具体指标 | 能抓的事故 | 抓不到的 | 成本 |
|---|---|---|---|---|
| **统计类** | 空值率、默认值率、均值、分位数 | 任务挂掉、字段全空（事故 1） | 分布内的任何变化 | 极低 |
| **分布类** | PSI、KS、KL、Wasserstein | 口径变更、分布平移（事故 2） | **分布没变但语义错位** | 低 |
| **一致性** | 离线/在线特征逐样本对拍 | 训推不一致（事故 3） | 上下游都错的情况 | 中（要采样落双份日志） |
| **关联类** | 特征-label 互信息、单特征 AUC 的漂移 | 语义错位（事故 3、4） | — | 中（需要 label，有延迟） |
| **业务兜底** | 影子流量上的实时 AUC/GAUC | 一切 | 事后才知道 | 高，但必须有 |

**核心结论：没有任何单一指标能兜住，必须分层组合。** 而且成本从上到下递增，
所以工业上的实践是"便宜的全量做，贵的采样做"。

## 五、怎么读输出

### 主表

```
事故类型                                  AUC     ΔAUC   最大PSI   责任特征    判定
无事故 (基线)                           0.8743  +0.0000    0.001  feat_10    正常
特征缺失: feat_0 全部变默认值            0.7763  -0.0979   12.434   feat_0    报警   ← 抓到了
口径变更: feat_1 分布平移+缩放           0.8333  -0.0410    1.362   feat_1    报警   ← 抓到了
离在线不一致: feat_2 有 30% 流量取到脏值  0.8528  -0.0215    0.001  feat_10    正常   ← 漏了！
特征不新鲜: 全特征叠加噪声                0.8504  -0.0239    0.007   feat_0    正常   ← 漏了！
```

**看后两行**：AUC 掉了 2 个点以上（线上这是重大事故级别），PSI 却判定"正常"。

### 为什么 PSI 抓不到事故 3

demo 里直接把证据打出来了：

```
训练期均值 -0.0021 / 线上均值 -0.0033
训练期方差  0.9997 / 线上方差  1.0012
PSI = 0.001  (判定: 正常)
但 AUC 掉了 -0.0215
```

被污染的 30% 流量，脏值恰好来自**同一个边缘分布** N(0,1)。所以：

- feat_2 的**直方图**和训练期几乎完全一致 → PSI 看不出来；
- 但 feat_2 和 label 的**关联**断了 → 模型用它做出的判断全错。

> **PSI 是单特征边缘分布指标，对"分布没变但语义错位"这类事故天然盲视。**
> 而这恰恰是推荐系统最高频的一类事故（特征版本错位、离线在线实现不一致）。

### 指标横向对比表（"必须分层组合"的**证据**）

对每种事故，都在**真正被污染的那个特征**上算各项指标（而不是取全特征最大值），
这样比的是指标本身的灵敏度，而不是"碰巧哪个特征噪声大"。

```
事故                        ΔAUC   默认值率Δ    PSI      KS   JS散度  Wasserstein  单特征AUCΔ  互信息Δ
特征缺失 feat_0 变默认值    -0.0979    *1.000 *12.434  *0.502  *0.526      *0.794     *0.233  *0.080
口径变更 feat_1 平移缩放    -0.0410     0.000  *1.362  *0.482  *0.155      *1.958      0.001   0.000
离在线不一致 feat_2 30%脏   -0.0232     0.000   0.000   0.006   0.000       0.007     *0.051  *0.018
特征不新鲜 全特征噪声       -0.0233     0.000   0.005   0.018   0.001       0.051      0.008  *0.006

抓到几种事故 (共 4 种)                 1/4     2/4     2/4     2/4         2/4        2/4     3/4
```

这张表比任何论证都有力：

- **没有任何一个指标能抓到全部四种事故**（最好的互信息也只有 3/4）。
- **四个边缘分布类指标（PSI/KS/JS/Wasserstein）的结果高度一致** ——
  它们同时抓到、也同时漏掉同一批事故。**再加一个同类指标是冗余，不是补强。**
  这一点很重要：很多团队的监控看板上堆了七八个分布指标，其实只有一个指标的信息量。
- **唯一能看见事故 3 的是关联类指标**（单特征 AUC / 互信息），因为只有它们看的是
  "特征和 label 的关系"，而不是"特征自己长什么样"。
- **但关联类指标要等 label 回流**（推荐场景里可能滞后几分钟到几天），
  所以它救不了"立刻发现"，只能兜底和事后归因。

于是监控体系该怎么搭就被这张表直接决定了：

```
便宜 + 实时  →  统计类 / 分布类（选一个分布指标就够，别堆）   全量
    ↓
中等 + 实时  →  离在线逐样本对拍                            采样
    ↓            ↑ 唯一既能实时、又能抓语义错位的手段
昂贵 + 滞后  →  关联类（单特征 AUC / 互信息）+ 影子流量 AUC    兜底
```

### 敏感度曲线

```
  污染比例       PSI       AUC      ΔAUC
  0%          0.001    0.8743   +0.0000
  10%         0.001    0.8607   -0.0136
  50%         0.001    0.7873   -0.0870
  100%        0.001    0.7134   -0.1609
```

**污染比例从 0 到 100%，AUC 单调掉了 16 个点，PSI 全程约等于 0。**
这一条曲线就是整个 demo 的结论 —— 一条水平线和一条下降线并排放着，
比任何论证都更有说服力。

## 六、动手：改参数能验证什么

| 参数 | 调成 | 会发生什么 | 说明了什么 |
|---|---|---|---|
| `SKEW_RATIO` | 0.3 → 1.0 | 事故 3 的 AUC 掉幅大幅增加，**PSI 仍然接近 0** | 盲区和污染程度无关。哪怕 100% 污染，只要边缘分布不变，PSI 就是瞎的 |
| `PSI_BINS` | 10 → 50 | 事故 3 的 PSI 还是抓不到 | 这不是"分桶不够细"的问题，是**指标维度**的问题。调参救不了 |
| `N_FEAT` | 12 → 64 | 最大 PSI 的噪声底噪抬高，误报变多 | 特征越多，"取最大 PSI 报警"的假阳性越严重。真实系统有几千个特征，阈值必须按特征分别定 |
| `N_SERVE` | 调小到 5000 | PSI 抖动明显变大 | 小样本下 PSI 本身不稳定，容易误报。监控要有最小样本量门槛 |

## 七、可以往下挖的点

表格里说的"亟需系统性数据质量评估与改进方法"，真正的技术含义是：

> 要建的是一套能把 **"数据异常量" → "业务指标掉幅"** 的**可量化映射**，
> 而不是一堆零散的阈值告警。

因为你必须能回答："这个特征的 PSI=0.3，到底会掉几个点 AUC？要不要半夜叫人起来？"
现在的现实是没人答得上来，所以要么报警疲劳（狼来了），要么漏掉真事故。

**顺带一提**：这个问题和表格 LLM 页里抖音推荐的方向五
（"建立算子精度损耗到离在线 AUC 波动的影响预测模型"）是**同构**的 ——
一个是数据侧扰动 → AUC，一个是数值精度扰动 → AUC，方法论完全可以复用。
